# air — 多開口機票組合規劃

省機票錢的核心手法是**不要買制式來回票**:去程降落地 ≠ 回程出發地(開口),
或把各段拆成獨立單程票分開買(拼票)。難處在於組合太多 —— 光是「台北 → 日本
兩城」就有(出發機場 × 抵達機場 × 日期 × 回程城市 × 日期)數千種排列,人工比不完。

這個工具做的事:**選國家 → 選機場 → 選日期區間 → 列出便宜組合並排名**,
並把「拼票」與「一張票」兩種買法並排比較。

站點:<https://air.aibubu.cloud/>

## 為什麼是這個架構

2026 年的免費機票 API 版圖比想像中窄,這直接決定了設計:

| 事實 | 影響 |
| --- | --- |
| Amadeus 自助 API 已於 **2026-07-17 全面關閉** | 最常被引用的免費多段查價路線已死 |
| Kiwi **Tequila 改邀請制**(經 Travelpayouts 需 5 萬 MAU) | 唯一做「虛擬聯程」的 API 拿不到,拼票必須自己算 |
| Travelpayouts 參考資料 **免認證**,查價需 token | 選單資料零門檻,價格要註冊 |
| Travelpayouts 價格是**快取價**(48 小時內搜到的) | 只能當參考價與排名依據,不可宣稱可訂 |
| Duffel 搜尋免費、只有開票收費,但 live 要驗證商業實體 | 當成加值,不當成前提 |
| Duffel test mode 是**虛構航空、價格不真實** | 沒有 sandbox 開發再切 live 這條路 |

所以是**兩層架構**:

1. **層一(免費、廣掃)** — Travelpayouts 快取價。一次呼叫回傳一條航線整月的
   每日最低價,所以日期維度的組合爆炸是免費的,只有「機場對」才花呼叫數。
   台北→日本兩城大約 30–40 次呼叫,不是幾千次。
2. **層二(即時、窄查)** — 對你點選的組合取實價。預設實作是**深連結**
   (Google Flights / Kayak / Aviasales),不需要任何金鑰;裝了 Duffel live
   token 之後自動升級成站內顯示即時報價。

層二寫成可抽換的 adapter,所以**有沒有 API 金鑰,產品都是完整的**。

## 誠實性規則(寫在程式碼裡,不只是文件)

- **查無資料 ≠ 不便宜。** 沒有價格的組合會顯示成「此航段查無資料」,絕不靜默丟掉。
  程式碼裡「問過但沒有」(`no_data`)和「根本沒問」(`not_fetched`)是兩種狀態。
- **不做部分加總。** 任一段沒價格,總價就是 `None`,不會把有資料的幾段加一加
  讓殘缺行程看起來最便宜。
- **價格與時效不可分離。** 每個價格都帶來源與抓取時間。
- **沒有價格的地方一定有理由。** `Quote` 這個型別在建構時就強制這件事。
- **超過上限就報錯,不截斷。** 靜默截斷的搜尋結果,長得跟「沒有更便宜的」一模一樣。

## 開發

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest -q
```

資料源實測(需要 `TRAVELPAYOUTS_TOKEN`):

```bash
python scripts/spike_datasource.py --out ../docs/spike-datasource.md
```

## 金鑰放哪裡

站台是**公開的、沒有登入**,所以金鑰預設不存在伺服器上:網頁右上「查價金鑰」
面板填入後存在該瀏覽器的 localStorage,查價時當成 `X-Travelpayouts-Token`
標頭送出,伺服器用完就忘。換裝置要再填一次,這是刻意的代價 —— 存在伺服器就等於
任何找到面板的人都讀得走。

`.env` 裡的 `TRAVELPAYOUTS_TOKEN` 仍然有效,當成備援;填了就是**對所有訪客生效**,
也就是大家共用你的 API 額度。

沒有任何金鑰時:參考資料層與深連結完全可用,查價會明確說「還沒有 token」而不是
安靜地回空。
